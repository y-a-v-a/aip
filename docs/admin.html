Admin guide

1. Becoming the admin

Admin rights can only be given from the command line on the server. No web page can create or promote an admin, so a leaked login link can never be turned into admin access.

On the shared host, over SSH, in the directory the app is deployed to:

php tools/make_user.php +31612345678 <your-pin> --admin

This creates the account, or — if it already exists — sets the PIN and the admin flag while keeping everything else (name, signed-in devices). An email address works as the identifier too. The admin needs a PIN: it is asked for again on the admin page.

No SSH? Run ./tools/adduser.sh +31612345678 <pin> --admin on your own machine (needs Docker, not PHP) and upload the resulting data/users.json — but only while nobody has been added via the web yet, because the upload replaces the file on the server.

Local Docker and the test suite seed an admin automatically: +31644444444 / 123456 (dev only — never on the host).

2. How the admin page is protected

The admin link in the menu is only shown to admins. Other signed-in people who type the address get a plain 404, as if the page did not exist.

3. Inviting someone

  1. Sign in, choose Admin in the menu and confirm your PIN.
  2. Under Add a person, enter a phone number in international format (+31612345678 — spaces and dashes are fine, a leading + is required) or an email address.
  3. Optionally add a name (used in the welcome message) and a PIN (at least 6 characters) if they should also be able to sign in on other devices without a new link.
  4. Press Add & create login link. A box with the link appears:
    • Copy link — paste it wherever you like;
    • Send via WhatsApp (phone numbers) — opens WhatsApp with a ready-made message to that number;
    • Send by email (emails) — opens your mail app with subject and message filled in.

The link is shown only once — the server keeps just a fingerprint of it. Missed it? Press New login link for that person.

The server never sends messages itself: WhatsApp and email go out from your phone or computer, so they arrive from someone the person knows.

5. Managing people

The list under People with access shows everyone, sorted by phone/email. Each row looks like this:

TagMeaning
adminMay open the admin page (set only via the command line).
PINCan also sign in with phone/email + PIN. No tag = link-only.
N devicesDevices on which they stay signed in (max. 10; oldest dropped first).
link pendingAn unused, unexpired login link exists.
ButtonEffect
New login linkMakes a fresh one-time link (valid 7 days) and shows it with the send buttons. Any older link stops working. Devices already signed in stay signed in.
Sign out everywhereEnds all their sessions and remembered devices immediately and cancels a pending link. They keep their account; send a new link to let them back in. Using it on yourself keeps your current session.
RemoveDeletes the person (after a confirmation). They are signed out on their next click. You cannot remove yourself.

Adding someone who already exists is refused (“already has access”) — use New login link instead. Changing a person’s name or PIN is not possible on the page; remove and re-add them, or use make_user.php.

7. Good practice

  • Send a link only to its owner. Whoever opens an unused link first becomes that person on their device.
  • Lost or stolen phone? Sign out everywhere, then send a new link to their new device.
  • Pick a strong admin PIN — longer than 6 characters is fine and wise.
  • Back up data/ on the host now and then (users, recipes, pantry, cost log).
  • Don’t overwrite the server’s data/users.json with a local copy once people have been added on the web.
